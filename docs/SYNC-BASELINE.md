# Experiment 001 — Wire Sync Baseline (research-only)

Status: **synthetic measurement instrument**, not a hardened protocol, a
production sync engine or an original compression algorithm.

## Purpose

Test whether reusing receiver-held data saves transmitted bytes after counting
what the receiver advertises, what the sender transmits, and the context the
receiver must retain. A plausible result is *worse* performance than full
Zstandard frames; no favorable assumption is hardcoded.

All data comes from the ten deterministic fixtures generated by
`benchmark.evolving_corpora()`. Nothing crosses project, tenant or clinical
data boundaries. There is no real network service.

## Version-1 experimental binary messages

All integer fields are little-endian. Digests are 32-byte SHA-256 values.

* **Advertisement**: 5-byte `IVAD1`, scope digest (32), entry count (u32),
  then sorted unique chunk IDs (32 bytes each). The receiver verifies its
  local blocks before claiming them. A corrupted block is not advertised.
* **Delta packet**: 5-byte `IVDL1`, scope digest (32), whole-snapshot
  SHA-256 (32), original byte length (u64), fixed chunk size (u32),
  reference count (u32), new-chunk count (u32), ordered 32-byte references,
  followed by new chunks. Each chunk carries its SHA-256 ID (32), raw byte
  length (u32), compressed-frame length (u32) and an independent Zstandard
  level-3 frame. Repeated chunks in one packet need only one frame.
* **Stateless full packet**: 5-byte `IVFL1`, scope digest (32), whole
  snapshot SHA-256 (32), raw length (u64), Zstandard frame length (u32),
  and one whole-object Zstandard level-3 frame.

Scope hashes are identifiers only; they do NOT constitute authentication.
Because this is synthetic-only, formats are unstable, no encryption exists,
and the Zstandard CLI decoder does not bound decompressed output. The
protocol and decoder MUST NOT be exposed to adversarial content.

## Measurement definitions

* **Full**: every revision independently encoded into a full packet. No
  receiver context or advertisement needed.
* **Cold**: each revision transferred to a fresh receiver with an empty
  cache, counting its advertisement plus its delta packet.
* **Warm**: the same five revisions transferred sequentially to the same
  receiver, counting all five evolving advertisements and delta packets.
* **Context storage**: lower bound of retained raw block bytes plus 32
  digest-ID bytes per unique block. Excludes Python dictionary, allocator,
  disk, filesystem and durability overhead. Reported separately and
  must not be quietly interpreted as zero cost.
* **Loss recovery**: clear receiver context and measure a complete resend of
  the final snapshot; stale references fail rather than reconstruct
  silently.
* **Scope rotation**: transfer the last snapshot to an independent scope
  with no reused cache; synthetic namespace separation is not an ACL.

All three paths verify exact original output. The delta receiver applies
new cache blocks only after verifying every new chunk and complete snapshot,
so failures do not partially commit new receiver state.

The report counts header bytes, 32-byte reference entries, advertised keys,
chunk framing, and payload bytes. Network stack, TLS, authentication, packet
loss, retry control, installation and persistent context are not measured.

## Falsifiability and limitations

A better future method must beat the full-Zstandard and carefully specified
sync baselines under matched resource limits, including context and
publication-grade measurement of CPU, memory, energy and transfer. At present
this is a **fixed-block** strategy; byte insertions shift boundaries and
can destroy reuse. It is deliberately not optimized to win.

The benchmark cannot establish a scientific discovery, Weissman score,
production reliability, confidentiality, or general-purpose superiority.

## Reproduce

Requirements: Python 3.11+ and Zstandard CLI.

```sh
python3 -m unittest discover -s scripts -p 'test_*.py'
python3 scripts/sync_baselines.py
```

Existing `scripts/benchmark.py` and `scripts/history_baselines.py`
remain separate baselines with different measurement boundaries.
